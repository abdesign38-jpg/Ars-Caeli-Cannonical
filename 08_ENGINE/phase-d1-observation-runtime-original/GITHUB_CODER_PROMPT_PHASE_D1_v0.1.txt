ARCHITECTURE:
- browser-native ES modules;
- append-only Journal is source of truth;
- Response Series is projection;
- IndexedDB is durable store;
- MemoryStore mirrors the storage interface for core tests;
- every state-changing command persists atomically;
- optimistic Session revision blocks multi-tab overwrite;
- every runtime load gets new runtime_epoch_id;
- store performance.timeOrigin + performance.now per event;
- valid RT cannot cross runtime epochs;
- exact Probe/Trial/Stimuli are snapshotted by SHA-256;
- export includes Session, Response Series, Journal, Artifact Snapshots and component hashes.

STATE MACHINE:
CREATED -> READY -> ARMED -> OBSERVING -> RESOLVED -> READY -> FINALIZED

Abort-before-onset:
ARMED -> RESOLVED -> record commit -> READY

All attempts produce immutable history. Retry creates a new attempt.

OPEN OBSERVATION CHANNEL:
Implement CONTEXT_MARKER with:
source:
  participant | operator | runtime

kind:
  technical | environmental | phenomenological | procedural | unexpected

Markers are JOURNAL ONLY.
They never automatically become behavioral records, participant observations,
derived metrics, or symbolic claims.

PARTICIPANT OBSERVATIONS:
D.1 must also support explicitly committing a stable-v0.1 participant observation
to response_series.observations.

RECOVERY:
On startup replay Journal and compare materialized caches.

If prior state:
- ARMED -> journal recovery, abort-before-onset record
- OBSERVING -> journal recovery, aborted record preserving onset
- RESOLVED -> reconstruct and commit the already-captured resolution

Do not invent cross-reload timing continuity.

PERSISTENCE:
IndexedDB:
- sessions
- events
- artifacts
- projections

One logical command = one readwrite transaction across required stores.

Before opening the transaction, finish hashing/validation/WebCrypto work.
Inside the transaction, do not await unrelated async work; enqueue only IndexedDB requests/synchronous bookkeeping.
Request strict durability where supported and record fallback capability.

At Session creation, check/request StorageManager persistent storage and record persistent|best_effort|unavailable.

Do not rely on unload/beforeunload for primary persistence.

CONCURRENCY:
Every command takes expectedRevision.
Check revision inside transaction.
Mismatch => SESSION_CONFLICT with zero writes.

INPUT:
Browser adapter:
- keyboard
- pointer
- touch
- first valid response wins
- listener cleanup deterministic
- no scoring

HASHING:
Use RFC 8785 / JCS for every content-addressed hash.
- JavaScript: canonicalize 5.0.0
- Python validation: rfc8785 0.1.4
- UTF-8 canonical bytes -> SHA-256
- add shared golden vectors for numbers, exponent forms, -0 policy, nesting and Unicode

Do NOT maintain a second hand-written canonicalizer.

Hashes = tamper evidence, not signatures.
